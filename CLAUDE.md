# pf-privilege-obo-LAB

Demo-tier standalone: simulated PingFederate → Privilege OBO chain (flow sim + measured-issues panel).

- Run: `npm ci && npm start` (port 7812) or `docker compose up --build -d`
- Test: `npm test` (node --test + vitest + repo checks), `npm run doctor`
- Rules that bite: Mock by default; Real runs live OBO against YOUR tenant only when this lab's `.env` is complete (else 409), loopback-only publish, no raw tokens in MOCK run records
  (claims + sha256/8 only; Real frames show real demo tokens in full), vendored `web/standalone-ui.css` must match the family canonical
  (`npm run test:repo` checks it), scenario data lives in `server/src/scenarios.js`.
- What Privilege did (Rule 25 panel): `POST /api/run` attaches `trace` (built by `server/src/oboTrace.js` from the hops `runChain` computed) and `FlowSim.jsx` renders `<GatewayTrace>` under the run result. The files are vendored byte-for-byte from AI-DEMO-Standalone `shared/gateway-trace` and pinned by `web/src/gateway-trace/gateway-trace.sha256` (`test/gateway-trace.test.js`): `web/src/gateway-trace/*` and `server/src/gatewayTrace.js` (NOT `trace.js`). Never hand-edit them; re-vendor with cp, then re-pin. Honesty rule: the MOCK decisions are `checked` only because `runChain` computed them (a check an earlier refusal never reached is `skipped`); a real gateway reports no per-check detail, so Real (`oboReal.js`) labels its checks `inferred` and reports only accepted or refused. No token (not even the garbage control) goes in a trace, only its length.
- Run observability (rule 27): `server/src/runLog.js` (the lab's half: one stdout line per decision, `observeMockRun` / `observeRealRun`, `buildRunRecord`) feeds the vendored shared collector; `GET /api/run-observability` returns the latest run's record in the current mode (204 when none). Vendored byte for byte and pinned: `server/src/runObservability.js`, `server/src/runObservabilityReaders.js`, `scripts/run-observability-checkPin.mjs`, `web/src/run-observability/*` (re-vendor with cp from AI-DEMO-Standalone `shared/run-observability`, then check `node scripts/run-observability-checkPin.mjs .`). Honesty rule: Mock rows are `simulated`, Real rows are `response` (a reply the lab received) or `logged` (read from a product log); never invent a row for a missing line.
  The ONE network exception for observability: the vendored `runObservabilityReaders.js` reads a LOOPBACK `RUN_OBS_ES_URL` with its own `fetch` (through the guarded netguard fetch, which lets loopback through and nothing else), in Real mode only, never in Mock, with a read-only `RUN_OBS_ES_READ_APIKEY`. Both settings are EMPTY by default in `docker-compose.yml` and `.env.example` (a test pins this: a default URL fails it); the Docker socket is never mounted (a test pins that too; `RUN_OBS_DOCKER=1` is for a throwaway ad-hoc override only). `GET /api/run-observability?runId=<id>` returns that run's record if it is one of the last 3 of the current mode, else 204 (reason in the `X-Run-Observability-Note` header), a bad id 400; without `runId` the newest finished run. Only a policy point's decision is `allowed`/`refused` (the exchange, workload-token check, grant, Cedar, the door, the backend): a sign-in or client-credentials issuance is `info`, and a PingFederate exchange is `refused` only for invalid_grant, invalid_target, invalid_scope, access_denied (the Real frame carries the OAuth `error`). A Real run that started before Reset never re-enters the stores; a mode switch during a Real run is a 409 `run_in_progress`; `runReal` checks its deadline before EACH call (a call that would start after it is not made: a `deadline` frame, an `info` row); a Real record is kept 10 s per run (`?fresh=1`, the page's Re-read, rebuilds it; Reset drops it); the made-up-credential control row is a genuine `refused` that is counted in the summary and says it is the lab's control. An `act` claim is read only if it is an object with a string `sub` (`"{}".sub` is `String.prototype.sub`).
- Real OBO (`server/src/oboReal.js`, `web/src/RealObo.jsx`): settings `PFO_USER_*` and `PFO_OBO_*` from the lab `.env` (or the environment; `PFO_ENV_FILE` overrides the path, tests point it at /dev/null). Two shapes (`agent`, `gateway`) run as numbered frames; `POST /api/real/obo/run {shape, refusal}`. The netguard allows only the configured hosts once Real is on (lookups included). Tokens ARE shown in full in a frame (demo; owner 2026-11-22: tokens may be shown, the family shows them raw); client secrets and the password never reach a frame (tests assert it). Tests use an in-process stub of PingFederate and the doors (`test/obo-real.test.js`). The video build is `video/` (SCRIPT.md first; `video/assets` and `video/out` are gitignored). Settings are never committed: the repo is public and forbids tenant identifiers.
